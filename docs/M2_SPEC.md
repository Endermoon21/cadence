# Cadence M2: fetch pipeline (CLI)

`cadence fetch` downloads the tracks the ledger says are missing, through the Tidal gate, into staging, then verifies, tags, places and records them. Context: `DESIGN.md` §5 (Fetch, Folder naming, Editions), §6 (gate), §7 (M2).

```
cadence fetch [--artist NAME | --release TIDAL_RELEASE_ID] [--quality HI_RES_LOSSLESS|LOSSLESS|HIGH]
              [--staging DIR] [--library DIR] [--execute] [--limit N] [--include-variants]
```

**Dry run is the default.** Without `--execute` it prints the plan (target path, `would fetch` / `exists, skip`, Tidal track id, duration, destination), every skipped track with its reason and Tidal id, and the planned/owned/skipped counts, and makes no network call, no login and no write. `--library` (else `$CADENCE_LIBRARY`) is needed so it can say whether each target exists; `--staging` (else `$CADENCE_STAGING`) only for `--execute`. There are no built-in paths.

**Plan** (`fetch/plan.py`): the planner reads only the ledger. A recording cluster (`COALESCE(canon_id, id)`, `cadence regroup`) is owned when at least one `file` row has `recording_id` set to a recording in it, library-wide; nothing else counts as owned. It never matches files by tags, names, durations, folders or title relations: `cadence link` is the only identity resolver, and files it could not resolve (ambiguous ones are in `link_review`) own nothing. The policy for ambiguity is duplicate-or-conflict: a track whose only file is unlinked is planned, never skipped on a guess, and if its target path is taken the executor reports `conflict` (the planner does not look at the disk). Collision rule: a planned track whose target path equals the path of a file the ledger links to a different recording (ledger only, `file.path` with `recording_id` set) is still planned, is listed in `Plan.collisions` (sorted by target, then Tidal id), and is printed as a `collision` line before the counts in both the dry run and execute, with a `collisions` count in the plan line (items with a collision, an item with two counted once); it may be a `conflict` at execute (exit 1; `--limit` can leave it unattempted), never overwritten, never silently skipped. Two planned tracks of different recordings with the same target path, compared case-insensitively (e.g. "Two" on `Alpha` and on `Alpha (Deluxe)`) are listed too, as a `duplicate target` collision (`Collision.kind == 'duplicate'`, the later track's Tidal id with the first track's path; the earlier one keeps the path and the later one is a `conflict`, in the dry run (printed `conflict` and counted in its conflict count) and at execute alike; the dry run only does so when the earlier item would itself be fetched, since an earlier item that is `fiio-only`, outside `--limit` or failed places nothing and the later one is then fetched). A missing cluster becomes one item, using the canonical recording's Tidal track (latest remaster), preferring album over EP over single over compilation. The target is `Artist/Album/NN - Title.ext` from `ledger/naming.py` (artist and release title from the ledger, edition and remaster markers stripped; `D{disc}-` prefix on multi-disc releases); the title carries Tidal's version (`Song (2009 Remaster)`). Only artists with `tidal_match` auto/manual are planned; every unowned cluster of any other artist is skipped with `artist not matched to Tidal (set it with cadence artist set-tidal)` (its owned clusters are counted as owned). Default scope is `partial`: only release groups that are partially owned, which means a linked file's recording (`file.recording_id`) is itself a track on a release of the group; a track of the release that is merely in an owned cluster (the same song linked on another release) does not make it partial, so owning one song does not pull in the box set that also carries it (the owned cluster itself is still owned and never planned); `--scope all` plans everything; `--release` is an explicit request. No silent skips: `plan_missing` returns a `Plan` with three buckets, and each recording cluster of the artist is in exactly one of them: `owned` (counted in the summary, not listed), `items` (planned), or `skipped` (listed with its reason and Tidal id, and counted per reason). Skip reasons: `partial scope: release has no owned track`, `variant (use --include-variants)`, `unavailable on Tidal`, `no tidal id`, `hidden release`, `appears-on release (name it with --release)`, `release not in --release`, `artist not matched to Tidal (set it with cadence artist set-tidal)`. A cluster counts once however many editions carry it. A recording shared by several artists (a collab on each one's release) is planned under one artist only: the recording row's artist if it plans the cluster, else the first artist that does; the others skip it with `shared recording, planned under <artist>`. Ownership is global (any linked file in the cluster, whoever the file's artist is), so an owned shared recording is never planned or skipped as shared. `owned` is artist-wide, whatever `--release` or `--scope` say, and is counted per artist that carries the cluster, not per cluster: a collab recording that sits on two artists' releases and is owned adds 2 to `owned`. Run `cadence sync-catalog`, `link` and `regroup` first, or "missing" is stale.

**Stream** (`fetch/stream.py`): `resolve_stream(session, track_id, quality)` reads `tracks/<id>/playbackinfopostpaywall` with the requested `audioquality` and returns `StreamInfo`. It refuses encrypted streams, previews, non-stereo audio and manifest layouts it does not understand; it never decrypts. Direct-URL manifests are downloaded as is; DASH (hi-res) manifests are fetched as init + numbered segments by plain GET and remuxed (stream copy) by ffmpeg into `.flac`/`.m4a`.

**Run** (`fetch/run.py`): per track: if the target is already on disk or in the ledger, make no Tidal call: `exists` when the ledger links it to this track, `conflict` when it is occupied by anything else (nothing is fetched; if it only becomes occupied after the download, even at the last instant before the link, the verified copy stays in staging and the event and note name its path), `gate.call` the playback request, `gate.call` the download to `staging/<target>.part`, atomic rename in staging, ffmpeg decode check plus duration within 3 s of Tidal's, mutagen tags (FLAC: ALBUMARTIST = primary artist, TITLE, TRACKNUMBER, DISCNUMBER, ALBUM, ISRC; M4A: the equivalent atoms), place into the library. On one filesystem that is `os.link` (no-clobber) then unlink the staged copy. Across filesystems (Unraid: staging on cache, library on the array) it copies to a `.part` file in the library, fsyncs, checks the size, links it into place with no-clobber, and unlinks the source only after the link is committed. Hard links are probed in preflight, and preflight refuses a staging directory that is inside or equal to the library. Then insert the `file` row (`source=tidal`, `match=manual`, `match_score=1`, `quality_requested`, `quality_received`), `fetch.placed` event, commit. It writes only under staging and library and never overwrites or deletes. A `fiio`-only item is not fetched yet, but in the dry run and at execute it still gets the occupied-path check (the dry run prints `conflict` and counts it, and writes nothing): a target taken by a file the ledger does not link to its cluster is a `conflict` (event `fetch.conflict`, exit 1); otherwise it is skipped and counted as `fiio-skipped` in the summary line. Its collision line reads `(fiio-only, checked in dry run and at execute)`. If preflight fails, or the CLI cannot start (gate paused, login failed) after the plan was built, the skip, collision and count lines are printed before the error.

**Stops and exit codes.** A 429 (or a paused gate) stops the run with exit 3 and lists the remaining items. A 401 on one track's playback request logs `fetch.blocked` for that track and goes on, unless the 401 body names the token or session: that is an auth failure and stops the run (exit 1). Other per-track errors log `fetch.failed` and go on (exit 1 at the end); a `conflict` also makes the run exit 1, with a line on stderr saying so (a run that pauses after a conflict reports it too, but exits 3); three dead connections in a row stop the run. Items whose destination is `fiio` only are skipped until M2b (the holding folder is not built).

**Quality gate.** For LOSSLESS and HI_RES_LOSSLESS requests, a lossy result (AAC) is not placed: it is staged as `<stem> [tidal <id>].m4a` and logs `fetch.held_lossy`, with no `file` row and no library write. A held track is skipped before any Tidal call on later runs. HIGH requests are exempt and place lossy files. Once a FLAC replaces a held copy, the staged AAC is removed (`fetch.stale_held_removed`).

**Naming.** Multi-disc albums use `D{disc}-NN - Title.ext`. The prefix appears only when the release has more than one disc. The disc count comes from Tidal's `numberOfVolumes`, with the highest disc number seen on the release's tracks as a floor (`plan.py`).

**Identity.** `cadence link` is the only identity resolver. When two or more distinct recordings tie for a file at the same rank it links none of them: the file stays `unmatched` and gets a `link_review` row (schema v6, reason `ambiguous`, candidates as JSON); `cadence link --review` lists them and changes nothing. The planner reads only those links and never re-matches files itself. Recordings of one cluster (`COALESCE(canon_id, id)`, e.g. the same song on a reissue) are one recording, not a tie: `link` links the file to the closest of them (the lowest id on an equal distance), and a tie needs two or more distinct clusters at the best rank. The same ISRC (after trim and upper-casing) on recordings of different clusters is a tie too. After upgrading to this rule, run `cadence link --rematch` once to re-evaluate old links (an old fuzzy tie link, a stale review row) with it; `--rematch` re-matches every file whose `match` is not `manual` (manual links, including every fetched file, are never touched). A file that already has a link keeps it when the re-match finds a tie: only the `link_review` row is written, so a tie never takes away a file the user owns; a file with no link goes to review unlinked. A linked file that matches nothing on `--rematch` (its tags changed) keeps its link too, with a `link_review` row of reason `no_longer_matches` (candidates: the artist's recordings with the same normalised title, possibly none); only a file that was never linked stays unmatched with no review row. `link --review` shows each row's reason and whether the file is currently `linked to <recording id>` or `unlinked`. A unique rematch that moves a linked file to a different recording is a correction, not an error: the link is changed and it is not reviewed. Resetting a file's link (`alias add`, or `import-legacy` seeing a changed artist) also deletes that file's `link_review` row.
